# Документация по базе данных проекта "За любовь"

Эта документация описывает структуру базы данных Telegram-бота проекта "За любовь". База данных хранит информацию о пользователях, платежах, подписках, продуктах и реферальной системе.

## Общая информация

База данных использует MySQL и работает через SQLAlchemy ORM. Все таблицы имеют поле `created_at` (Unix timestamp), которое автоматически заполняется при создании записи.

## Основные таблицы

### users (Пользователи)

Основная таблица пользователей бота.

**Поля:**
- `id` (Integer, PK) - Внутренний ID пользователя
- `tg_id` (BigInteger) - Telegram ID пользователя (уникальный идентификатор)
- `username` (String) - Username в Telegram (может быть NULL)
- `full_name` (String) - Полное имя пользователя
- `phone` (String) - Номер телефона
- `city` (String) - Город пользователя
- `balance` (Integer, default=0) - Бонусный баланс (в копейках)
- `inner_balance` (Integer, default=0) - Накопительный баланс (в копейках)
- `has_ended` (Boolean, default=False) - Завершена ли регистрация
- `ref` (BigInteger) - Telegram ID реферера (если 1, то системный админ)
- `ref_level` (Integer, default=1) - Уровень партнерской программы (1-6)
- `created_at` (Integer) - Дата регистрации (Unix timestamp)

**Особенности:**
- При регистрации пользователь получает бесплатную подписку на 30 дней (grace период)
- Уровень партнерской программы определяет, до какой линии рефералов пользователь получает бонусы
- Балансы хранятся в копейках (целые числа)

### pay_metadatas (Метаданные платежей)

Хранит информацию о созданных платежах до их оплаты.

**Поля:**
- `id` (Integer, PK) - ID записи (используется как orderNumber в YooKassa)
- `user_id` (Integer) - ID пользователя
- `price` (Integer) - Сумма платежа в копейках
- `product` (String) - Тип продукта (subscribe-1, subscribe-12, game, education:123 и т.д.)
- `procent_balance` (Integer) - Процент от суммы, который идет на реферальные бонусы
- `inner_balance` (Integer) - Процент от суммы, который идет на внутренний баланс
- `has_payed` (Boolean, default=False) - Оплачен ли платеж
- `created_at` (Integer) - Дата создания

**Типы продуктов:**
- `subscribe-1` - Подписка на месяц (30 дней)
- `subscribe-12` - Подписка на год (365 дней)
- `game` - Комплект ведущего игры
- `pocketgame` - Карманная игра
- `servicecard` - Сервисная карта
- `personalbot` - Личный бот ведущего
- `clubtraining` - Организатор клуба знакомств
- `citymanager` - Управляющий города
- `package` - Пакет партнерской программы
- `education:{id}` - Образовательный курс (ID курса)
- `strategy_partner:{id}` - Продукт стратегического партнера (ID продукта)
- `poster` - Создание афиши

### payment_records (Записи о платежах)

Хранит информацию об успешно оплаченных платежах.

**Поля:**
- `id` (Integer, PK)
- `user_id` (Integer, indexed) - ID пользователя
- `pay_metadata_id` (Integer, indexed) - Ссылка на pay_metadatas
- `payment_id` (String, unique) - ID платежа в YooKassa
- `product` (String) - Тип продукта
- `amount` (Integer) - Сумма платежа
- `created_at` (Integer)

**Особенности:**
- Используется для отслеживания истории платежей
- `payment_id` уникален, чтобы избежать дублирования записей

### auto_payment_methods (Автоплатежи)

Хранит информацию о сохраненных способах оплаты для автопродления подписки.

**Поля:**
- `id` (Integer, PK)
- `user_id` (Integer, unique, indexed) - ID пользователя
- `payment_method_id` (String) - ID способа оплаты в YooKassa
- `product` (String) - Тип продукта для автоплатежа
- `amount` (Integer) - Сумма автоплатежа
- `last_payment_id` (String) - ID последнего платежа
- `last_attempt_at` (Integer) - Время последней попытки автоплатежа

**Особенности:**
- Один пользователь может иметь только один активный автоплатеж
- Используется для автоматического продления подписки при истечении срока

Список городов, где работает проект.

**Поля:**

### posters (Афиши)

Афиши мероприятий по городам.

**Поля:**

### promocodes (Промокоды)

Промокоды для активации различных бонусов.

### balance_transafers (Переводы баланса)

История переводов баланса между пользователями.

**Поля:**

- `to_user_id` (Integer) - ID получателя
- `from_user_id` (Integer) - ID отправителя
- `money` (Integer) - Сумма перевода в копейках

**Примечание:** В названии таблицы опечатка (transafers вместо transfers), но это сохранено для совместимости.

## Реферальная система

Реферальная система работает по принципу многоуровневой маркетинговой структуры:

1. **Уровни партнерской программы (ref_level):**
   - 1 уровень - базовый (получает бонусы с 1 линии)
   - 2 уровень - получает бонусы с 1-3 линий
   - 3 уровень - получает бонусы с 1-5 линий
   - 4 уровень - получает бонусы с 1-7 линий
   - 5 уровень - получает бонусы с 1-9 линий
   - 6 уровень - получает бонусы со всех 20 линий

2. **Процентное распределение по линиям:**
   - 1 линия: 40% от суммы реферальных бонусов
   - 2 линия: 20%
   - 3 линия: 14%
   - 4-5 линии: по 6%
   - 6-7 линии: по 4%
   - 8-9 линии: 3% и 2%
   - 10-20 линии: уменьшающийся процент (от 0.5% до 0.000488%)

3. **Внутренний баланс (inner_balance):**
   - 1 линия: 40%
   - 2 линия: 40%
   - 3 линия: 20%
   - Остальные линии: 0%

4. **Логика распределения:**
   - Если реферер имеет достаточный уровень партнерской программы, бонусы начисляются ему
   - Если уровень недостаточен, бонусы идут администратору (user.id = 1)

## Подписки

Система подписок работает следующим образом:

1. **Grace период:** Каждый новый пользователь получает 30 дней бесплатной подписки с момента регистрации.

2. **Оплаченные подписки:** Подписки складываются (stacking):
   - Если пользователь купил подписку на месяц, а затем на год, общий срок = месяц + год
   - Подписки продлеваются от максимальной текущей даты окончания или от даты покупки (что больше)

3. **Проверка активности:** Подписка считается активной, если текущая дата меньше даты окончания.

4. **Уведомления:** Пользователи получают уведомления:
   - За 3 дня до окончания
   - За 1 день до окончания
   - После истечения срока

## Платежи

Процесс обработки платежей:

1. **Создание платежа:** При нажатии кнопки "Оплатить" создается запись в `pay_metadatas` и платеж в YooKassa.

2. **Проверка оплаты:** Отдельный сервис (`checker.py`) периодически проверяет статус платежей через API YooKassa.

3. **Обработка оплаты:** При успешной оплате:
   - `pay_metadatas.has_payed` устанавливается в `True`
   - Создается запись в `payment_records`
   - Начисляются реферальные бонусы
   - Отправляются уведомления пользователю и администраторам
   - Для курсов/продуктов создаются записи в соответствующих таблицах

## Важные замечания

1. **Денежные суммы:** Все суммы хранятся в копейках (целые числа). При отображении нужно делить на 100.

2. **Временные метки:** Используются Unix timestamps (секунды с 1 января 1970 UTC).

3. **Реферальная цепочка:** Максимальная глубина - 20 линий. Если в цепочке нет реферера, распределение прекращается.

4. **Уровни партнерской программы:** Повышаются покупкой соответствующих пакетов:
   - 5000₽ → уровень 2
   - 15000₽ → уровень 3
   - 25000₽ → уровень 4
   - 45000₽ → уровень 5
   - 100000₽ → уровень 6

5. **Автоплатежи:** Работают только для подписок. При истечении срока автоматически создается новый платеж с сохраненным способом оплаты.
